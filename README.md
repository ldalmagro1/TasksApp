# Notes App

A full-stack note-taking SPA built as part of the Ensolvers technical challenge.

## Features

### Phase 1 (Mandatory)
- Create, edit, and delete notes
- Archive / unarchive notes
- List active notes
- List archived notes

### Phase 2 (Bonus)
- Add / remove categories to notes
- Filter active notes by category

---

## Architecture

```
React SPA (Vite)  ←→  REST API (NestJS)  ←→  PostgreSQL
     :5173                 :3000/api               :5432
```

### Backend layer separation

| Layer | Responsibility |
|---|---|
| **Controller** | HTTP routing, input validation via `class-validator` |
| **Service** | Business logic (archive, filter, category resolution) |
| **Repository** | Database access via TypeORM (injected by NestJS DI) |

## Quick Start (Docker — Recommended)

**Requires:** Docker 24+ and Docker Compose v2+

```bash
# From the project root:
bash start.sh
```

Or manually:

```bash
docker compose up --build -d
```

| Service | URL |
|---|---|
| Frontend | http://localhost:5173 |
| Backend API | http://localhost:3000/api |

To stop all services:

```bash
docker compose down
```

## Local Development (without Docker)

### Prerequisites

- Node.js 20+ and the npm version bundled with it
- PostgreSQL 16 running locally

### 1. Set up the database

```sql
CREATE USER notes_user WITH PASSWORD 'notes_pass';
CREATE DATABASE notes_db OWNER notes_user;
```

### 2. Backend

```bash
cd backend
cp .env.example .env   # adjust values if needed
npm install
npm run start:dev
```

API available at: `http://localhost:3000/api`

### 3. Frontend

```bash
cd frontend
npm install
npm run dev
```

App available at: `http://localhost:5173`

> In local dev mode, Vite proxies `/api/*` requests to `http://localhost:3000` automatically — no CORS issues.

## API Reference

A fully interactive Swagger API documentation is automatically generated by NestJS and is available locally when the backend is running:

**Swagger UI:** `http://localhost:3000/api/docs`

You can use the Swagger UI to interactively explore and test all endpoints, DTO schemas, and response formats.

### Notes — `/api/notes`

| Method | Endpoint | Description |
|--------|----------|-------------|
| GET | `/api/notes` | List active notes (optional `?categoryId=<uuid>`) |
| GET | `/api/notes/archived` | List archived notes |
| GET | `/api/notes/:id` | Get note by ID |
| POST | `/api/notes` | Create note |
| PUT | `/api/notes/:id` | Update note |
| DELETE | `/api/notes/:id` | Delete note (204) |
| PATCH | `/api/notes/:id/archive` | Archive note |
| PATCH | `/api/notes/:id/unarchive` | Unarchive note |

### Categories — `/api/categories`

| Method | Endpoint | Description |
|--------|----------|-------------|
| GET | `/api/categories` | List all categories |
| POST | `/api/categories` | Create category |
| DELETE | `/api/categories/:id` | Delete category (204) |

## Commits Strategy

The project development follows a gradual, incremental commit strategy to ensure clarity, trace errors easily, and demonstrate a professional workflow. The general strategy is:

1. **Initial Setup:** Scaffold backend and frontend foundations independently.
2. **Backend Domain Implementation:** Incrementally add entities, modules, and API endpoints (e.g., core note CRUD, then categories).
3. **Frontend Integration:** Gradually connect the SPA with the backend APIs.
4. **Iterative Refactoring:** Isolate structural refactors (like moving from plain CSS to NextUI/Tailwind) into their own self-contained commits.
5. **Final Polish:** Containerization updates, documentation, and bug fixes as isolated patches.
